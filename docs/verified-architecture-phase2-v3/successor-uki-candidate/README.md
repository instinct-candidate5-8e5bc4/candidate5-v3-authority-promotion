# Minimal Cloud Boot Adapter and Successor UKI Implementation Candidate

Status: `CERTIFICATION_EVIDENCE_COMPLETE_RUNTIME_PASS`

This candidate is not authorized for execution, boot, signing, cloud use or provisioning. It contains no private key, PFX, public production certificate or signed successor UKI.

`cloud-boot-adapter.sh` is the new first init. It uses only the already pinned BusyBox closure, resolves six exact GCP persistent-disk identities only through the documented `/dev/disk/by-id/google-*` namespace, rejects unknown `v3-*` and non-unique identities, creates the two canonical dm-verity aliases, mounts four exact ext4 volumes with fixed modes, emits and syncs canonical non-secret `cloud-boot-adapter.v2` evidence with stable google-* role names and resolved major:minor identities, verifies the preserved old init digest and hands off to `/init.root-admitter`. The preserved old init then performs the unchanged dm-verity, mount, freshness and Root-Admitter checks.

`build-successor.py` parses the certified old CPIO directly, preserves every unchanged header field and body, relocates byte-identical `/init`, adds the adapter as `/init`, emits newc CPIO bytes and constructs the unsigned PE/COFF UKI with the byte-identical stub, kernel and command line. It writes a canonical inventory. Running it twice must reproduce all generated bytes.

The exact device names are:

- `v3-rootfs-data`
- `v3-rootfs-hash`
- `v3-reviewed-root`
- `v3-reviewed-input`
- `v3-reviewed-output`
- `v3-reviewed-evidence`

The six names and mount rules are literal embedded adapter constants. There is no separate runtime manifest that could drift from those constants. The adapter rejects any other provider link beginning `google-v3-`, resolves each expected symlink to its final `/dev/*` block object, verifies link/object identity and rejects aliases. Disks outside this reserved namespace are non-authoritative platform/boot devices and are ignored. There is no fallback to sysfs serials, incidental `/dev/sdX` or NVMe ordering, filesystem labels, metadata, DNS or network state.
